# /runbook

> **Principle 9.3**: Agents for everything — Operational Runbooks.  
> *"Status updates, sprint summaries, oncall reports, runbooks: all of it follows the same flow."*  
> **Source**: [kiro.dev/topics/frontier-engineering/agents-for-everything](https://kiro.dev/topics/frontier-engineering/agents-for-everything/)

## Purpose & Objective
"Do one thing and do it best": `/runbook` generates bulletproof, copy-pasteable **Operational Runbooks** (`docs/runbooks/<task-slug>.md`).
When engineers or on-call responders perform stressful operations (database migrations, data backfills, secret rotations, version rollbacks, disaster recovery), they need unambiguous steps with safety assertions, verification scripts, and exact rollback commands.

## When to Reach for It
- Preparing for a risky release, infrastructure migration, or major data backfill.
- Documenting disaster recovery or failover procedures.
- Standardizing repetitive on-call operational workflows.
- Triggered by typing `/runbook <operational procedure title>`.

## Standalone & Synergy Characteristics
- **Standalone**: Directly inspects scripts, docker-compose, migrations, and infrastructure configs to produce executable markdown runbooks.
- **Synergy with D-Level Suite**: Provides the operational procedures referenced in `/draft-rfc` and post-incident remediation steps generated by `/postmortem`.

## 1. Pre-Flight Verification Checklist
Run these commands to confirm system is ready before proceeding:
```bash
# Check replica health
curl -f https://internal-api.service/health/ready
# Verify disk space
df -h /var/data
```

---

## 2. Execution Steps

### Step 2.1: Snapshot & Backup
```bash
pg_dump -U postgres -d production_db -t target_table > backup_$(date +%s).sql
```

### Step 2.2: Apply Zero-Downtime Migration
```bash
npm run migrate:up
```

### Step 2.3: Verify Migration Health
```bash
npm run check:migration-integrity
```

---

## 3. Post-Execution Verification
Check that error rates and latency remain within nominal thresholds:
- Datadog / Grafana Dashboard URL: `https://metrics.internal/d/orders`
- Verify 200 OK on probe endpoint:
```bash
curl -i https://api.service/v1/healthcheck
```

---

## 4. Emergency Rollback Procedure
If p99 latency exceeds 200ms or error rate > 1%:
```bash
# 1. Revert deployment
kubectl rollout undo deployment/api-server
# 2. Revert migration
npm run migrate:down
```
```
